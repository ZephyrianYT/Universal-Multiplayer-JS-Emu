🦆 RetroDuck for beginners: pick your setupNew to RetroDuck? This guide helps you pick the right setup for what you want to play and walks through getting it running step by step. For a quick overview, see the README; for full configuration and internals, see the advanced guide.   RetroDuck does not include games, BIOS files, or keys. Only play games you own. Stations rely on Windows XInput controller routing.   1. Just RetroDuck (standalone)Use this setup for hosting games from one PC and inviting friends over a link.   Choose Co-op (host runs and streams the game), Ghost, or Race (each player runs their own copy side by side with low latency), pick a game, and open the lobby.   For remote friends without port forwarding, toggle 🌍 Internet link from ☰ Menu, then click Copy invite link in the lobby.   Native emulators for heavier consoles (such as PS2 or GameCube) run on your host PC and stream into the lobby; see section 8 in the advanced guide.   2. At home on your Wi-FiEnable ☰ Menu > 🏠 Wi-Fi name so devices on your home network can open [http://yourname.local](http://yourname.local) without a port number.   Open ☰ Menu > 📺 Big screen for a controller-friendly TV interface.   To let guests play curated browser games or join LAN rooms from their phones without exposing full library/owner controls, enable the Pond.   3. An arcade cabinetA single-screen, single-controller cabinet uses one station in seat mode so a physical controller always maps to Player 1.   1.Connect the Cabinet Controller:XInput or translator active.Connect an Xbox-style controller directly, or route PlayStation, Switch, or non-XInput arcade sticks through Steam Input or DS4Windows.2.Initialize One Station:Creates stations.json.Run python stations.py init --count 1 in your RetroDuck folder to generate stations.json with station1 on monitor 1 and port 8081.3.Switch the Station to Seat Mode:Walk-up Player 1 lock.Edit stations.json to set "mode": "seat" and "pad": 1 for station1 so controller 1 always acts as Player 1 without gesture claiming.4.Verify Plan and Sign In Once:Preview & first sign-in.Run python stations.py plan to preview actions, then run python stations.py start --windowed once to sign in inside the station's dedicated browser profile.5.Launch in Kiosk Mode:Full-screen operation.Run python stations.py start for borderless full-screen launch on Big screen; use python stations.py stop (or Alt+F4) to close.
Verification: The full-screen station window opens on the target monitor and responds to Player 1 inputs.Audio currently outputs through the host PC's default speakers (per-station audio routing is saved in stations.json but not yet wired to separate outputs), and you start the main hub before python stations.py start.   4. Several screens on one PCScale up to 4 monitors and stations on one Windows PC (matching Windows' 4 XInput controller slots):   Run python stations.py monitors to list available display numbers (1 is primary).   Run python stations.py init --count 2 (up to 4) to assign each monitor its own station and port (8081, 8082, and so on).   Configure "mode" per station in stations.json:Player mode (default): Players sign in on the station and press A (or a unique direction + A prompt when multiple stations wait) to claim Player 1 until sign-out.   Seat mode: Assign "pad": N so a dedicated controller always owns Player 1 on that station.   Run python stations.py start --windowed once per station to sign in, then use python stations.py start for normal runs, python stations.py status to inspect state, and python stations.py stop to shut stations down.   The pad router isolates controller input per station even when another window is focused, and local LAN players can also join station lobbies.   5. A LAN party with a MommaDockUse MommaDock as the central LAN view/controller alongside Duckling nodes (RH_NODE=1) and Pond so phones can join active rooms across machines.   Plaintext   NAS or hub PC: MommaDock (MOMMADOCK=1) ── LAN board, node adoption, Pond
        │  same LAN subnet (br0 / host network on Linux/NAS)
   ┌────┴────────────┬────────────────┐
   PC 1 (RH_NODE=1)  PC 2 (RH_NODE=1)  laptop / cabinet duckling
   stations 1-4      stations 1-4      hosted room or open unit
Prep before the eventSet up each PC's stations as in setup 4 and launch each needed browser console once while online so cores cache locally for offline LAN play.   Keep MommaDock and node PCs on matching RetroDuck versions.   Configure MommaDockNAS / Docker: Enable MOMMADOCK=1 and attach the container to Unraid br0 with its own LAN IP (or network_mode: host on Linux); Docker bridge networks and Docker Desktop VMs block LAN multicast beacons.   Windows / desktop hub: Set MOMMADOCK=1 in .env and restart RetroDuck.   Adopt nodes and run stationsOn each node PC, set RH_NODE=1 and a clear RH_NAME (such as RH_NAME=PC 1) in .env, then restart RetroDuck.   Open ☰ Menu > 🦆 MommaDock to see pending nodes with a 6-digit code.   Click Approve on MommaDock, then open ☰ Menu > 🐣 Duckling node on the node PC and click Accept only if both screens show the exact same 6-digit code.   Use Start stations, Stop stations, and Status from MommaDock to control allowlisted station actions on adopted nodes.   Using Forget on MommaDock or Leave on the node revokes pairing and requires a fresh code check and Accept to re-adopt. Adopted nodes only execute allowlisted station commands (start, stop, status) and cannot run arbitrary programs or read files remotely.   6. Just a NASA Docker deployment on a NAS (such as Unraid or Linux) hosts the web UI, lobby signaling, and ROM library without running native emulators—ideal for browser consoles where each player's device runs the core:   Copy .env.example to .env, set ADMIN_PASSWORD, and map your ROM directory to the roms volume in docker-compose.yml.   Run docker compose up -d --build.   Open http://<nas-ip>:8080, create your account, and open the Pond for phones and laptops on your network.   Add MOMMADOCK=1 (on br0 or host networking) later if you want the NAS to oversee additional ducks and nodes.   The Pond: guests on their phonesPond is the guest-facing portal (/pond.html) for local events and home Wi-Fi play. It is marked 🧪 while live Wi-Fi phone/second-PC checks and MommaDock/duckling tie-ins are being finalized.   Open ☰ Menu > 🌊 Pond on your hub or MommaDock.   Search your library and click + Add for up to 60 browser games (native console games, PC games, and hidden games are excluded).   Enter an event name and toggle Pond is open on.   Use 📺 Show on a TV for a large QR code and live game status; if warned that the URL is local-only, enable ☰ Menu > 🏠 Wi-Fi name or open Pond from a LAN-reachable address.   Guests scan the QR code, create an account with one tap, return to Pond, and can start an allowed browser game on their own device (with touch controls on phones) or join live rooms. On the LAN, On this network surfaces active rooms across ducks (Join, In use when full, 🔒 Locked) alongside idle ducks (Play here).   While Pond is open, non-library guests can access only curated Pond titles; closing Pond immediately revokes that access. General issues: See Need help? in the README and Troubleshooting in the advanced guide.   Node missing on MommaDock: Confirm both devices are on the same LAN, RH_NODE=1 is active on the node, and Unraid MommaDock uses br0 or host networking rather than Docker bridge.   Station ignores controller: Use Xbox-style controllers (or Steam Input / DS4Windows for other pads), and in player mode sign in before pressing A.
